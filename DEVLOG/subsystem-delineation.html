Today: one app, seven concerns

Every box below is real code in the fork. The problem is not that any of it is bad, it is that the parts another app would want are wired directly to the parts only a dictation app needs: a global hotkey, an overlay near the notch, and pasting into whatever had focus.

After the cut: a headless core with two consumers

The delineation is one seam, drawn between producing text from a microphone and deciding when to listen and where the text goes. Everything above the seam has no opinion about hotkeys, overlays, Accessibility or the menu bar.

What the surgery actually costs

SeamWhy it does not cut cleanly todayWork
AppSettingsStorage Resolves its file path from AppName.displayName, so the core would read whichever app happens to host it. Already bit us: renaming the app gave it an empty settings file. Inject a storage location instead of deriving one.
AppState 3500 lines holding recording state, transcription sessions, settings, overlay control and delivery in one object. The core's state is tangled with the app's. Lift session bookkeeping into the core; leave the SwiftUI-facing properties behind.
AudioRecorder Callback properties assigned from AppState (onRecordingReady, onPCM16Samples) and reset from several places, which is what made overlapping dictations tear the recorder down mid-recording. Expose an async sequence per session rather than shared mutable callbacks.
AppContextService Reads the frontmost app, window title and a screenshot. Meaningful for dictation, meaningless for TalkWeave. Make context an injected provider; the core takes whatever string it is handed.
PipelineHistoryStore Core Data model shaped around dictation runs. Either move it into the core as the canonical run log, or leave it in FreeFlow and give the core a delegate.

Why it is worth it, and why not yet

  • Worth it: the capture and transcription stack is the expensive part, and it already works against a local Qwen3 model with chunking, prefetch and a realtime path. Rebuilding that per project is the actual waste.
  • Worth it: the seam would force the overlapping-session bookkeeping to be explicit rather than implied by two booleans, which is where today's bugs came from.
  • Not yet: the delivery ladder is still being proven against real apps. Extracting a core while the layer above it is still moving means doing the surgery twice.
  • Not yet: a merge upstream is easier from a shape Zach recognises. A package split is a much larger thing to ask him to take.

Status: nothing extracted, nothing started. This page is the map, drawn so the decision can be made on what it costs rather than on how it sounds.
